    02Architecture

    What sits under a production agent

    A demo agent is a prompt and an API key. A production agent needs six more layers. I design, build and operate all of them.

    • LLM gateway

      One private entry point for every model: routing, fallback, per-team token budgets and cost attribution. Your prompts never hit a public multi-tenant endpoint unless you choose it.

    • MCP tool bus

      Agents act through typed tools (databases, twins, ticketing, IaC) exposed over the Model Context Protocol, each with its own auth and scope.

    • Memory & retrieval

      Exact operational facts, episodic history and hybrid vector search, so agents answer from your data with citations instead of guessing.

    • Guardrails & approval

      Read-only by default. Anything that changes production, money or customers stops at a human approval gate, and every step is logged.

    • Evals & observability

      Traces for every run, regression evals before each change, and latency and cost tracked per tool call.

    • Private inference

      Open-weight models on your own GPUs when data cannot leave, with quantization tuned for throughput.
